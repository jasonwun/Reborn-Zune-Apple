# M16 — 性能：瓷砖墙专项

## Background

M16 基线（`reports/M16_baseline.md`，2026-09-27 实测，Debug 构建，播放页静置）：

| 配置 | Footprint | 空闲 CPU |
| --- | --- | --- |
| 播放页，光照开（现状） | 476 MB | 22.6% 持续 |
| 播放页，光照关 | 58 MB | ≈0% |

瓷砖墙的全部空闲成本都来自光照效果。代码审查确认三个热点：

1. **`LightingModifier` 按屏幕刷新率驱动全屏 Metal shader**
   （`LightingModifier.swift:23`）。`TimelineView(.animation)` 最高
   120 Hz tick，每帧对整面墙重新应用 `colorEffect`，迫使整面子树
   离屏光栅化。光照周期 120 秒，30 fps 与 120 fps 视觉上无差别。
2. **扩展瓷砖 id 每次 body 求值重新随机**（`TileWallView.swift:11,
   73,146`）。body 被翻牌脉冲（每 5 s）与拖拽 resize 频繁触发，
   每次触发全部扩展瓷砖身份失效 → 整面墙销毁重建、入场动画重放。
3. **`expanded()` 无缓存**（`TileWallView.swift:73`）。窗口尺寸每变
   1 pt 重跑一遍数百块瓷砖的 RNG 采样与数组构建。

## Decisions (locked for this milestone)

| Area | Decision | Rationale |
| --- | --- | --- |
| 光照帧率 | `.animation(minimumInterval: 1/15)`，上限 15 fps | 120 s 周期的慢速光照，15 fps 视觉无损；30 fps 实测残留 ~13%、20 fps 残留 ~9%，15 fps 达标 |
| 扩展瓷砖 id | 由 (expansionSeed, index) 确定性派生 | 身份稳定后 SwiftUI 可增量 diff，翻牌/resize 不再重建整墙 |
| 扩展缓存 | memoize 在（cellsW, cellsH, unitSize, seed, source 身份）上 | 拖拽只在跨过 50pt 格界时重算，每 pt 重算消失 |
| 内存 | 本里程碑不定硬指标，实测记录 | colorEffect 的离屏纹理只要效果启用就常驻；节帧省的是时间不是驻留。若验收时内存仍不可接受，另立里程碑做降分辨率采样 |
| iPad / tvOS | 共享 `TileWallView`/`LightingModifier` 同一修复，行为参数一致 | 三端共用组件；视觉输出不变（M5 快照路径不经过 TimelineView，位级不变） |

## Scope

* `Sources/RebornZuneCore/Views/LightingModifier.swift`
* `Sources/RebornZuneCore/Views/TileWallView.swift`（扩展 id + 缓存）
* 新测试：`Tests/RebornZuneCoreTests/` 内覆盖 id 稳定性与缓存行为
* Out of scope：CoverArt 解码缓存、启动耗时、Home 屏性能、
  窗口遮挡时暂停动画（如有余力可做，非承诺项）

## Deliverables

### A. 光照节流

1. `LightingModifier.body` 的 `TimelineView(.animation)` 改为
   `TimelineView(.animation(minimumInterval: frameInterval))`，
   `frameInterval = 1.0/30` 作为 `static let` 暴露在类型上（供测试
   断言）。`staticSnapshot` 路径不得触碰。

### B. 扩展瓷砖 id 稳定化

2. `TileWallView.expanded` 合成 entry 时使用
   `TileWallEntry(id: Self.expansionID(seed: seed, index: out.count), …)`；
   `expansionID` 为纯函数：同一 (seed, index) 必得同一 UUID，不同
   seed 必不同。源列表原样返回的分支（source.count ≥ target）不变。

### C. 扩展缓存

3. 引入 wall 级缓存（如 `@State` 持有的引用类型 memoizer）：
   key = (cellsW, cellsH, unitSize, seed, source.count + 首尾 id)。
   key 命中时返回上次数组（实例复用），未命中才调 `expanded`。
   禁止在 body 求值期间写 `@State` 值类型（避免 "modifying state
   during view update"）。

### D. 测试

4. `expanded` id 稳定性：同参两调，id 序列完全一致；不同 seed
   不同 id；扩容后追加 tile 不改变已有 tile 的 id（索引位不变）。
5. 缓存：同 key 两调返回同一数组实例；cellsW 变化后返回新实例。
6. `LightingModifier.frameInterval == 1.0/30`。
7. 既有 115 项测试（含 M5 光照/快照系列）必须全绿。

## M16.1 Addendum (2026-09-27, 用户目检反馈)

1. **合成封面改为平色**。M16 follow-up 最初给 demo 封面画了不同角度的
   对角渐变——去饱和后每块瓷砖自带明暗方向，被用户误读为"光照平均
   作用在每块瓷砖上"（M5.20 已记录过此教训）。shader 坐标系经核对是
   全局的（`position` 在墙层坐标空间，灯光位置经 panelSize 缩放），
   光照本身不存在 per-tile 问题。修复：封面平色填充，色相/亮度/饱和度
   按专辑变化以保留去饱和后的明度多样性。
2. **瓷砖墙排列冻结**。进页面首次布局时以当时面板尺寸计算扩展与排列
   并冻结（`frozenPanelSize`），此后窗口 resize 不再重排：墙是固定
   背景，窗口只决定露出多少（topLeading 锚定 + clipped）。每次进入页
   面（新视图身份 → 新 @State）重新计算。窗口拉大超过冻结尺寸时多出
   的区域显示 M5.26 灰底——用户明确选择冻结而非重排，接受此取舍。
