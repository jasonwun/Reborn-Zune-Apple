# M15 — Content curation + physical-device path

## Background

The structural Resonant work (M9–M14) ships pixel-correct chrome but
populates the panorama from `library.albums.first` with generic
fallback strings:

```
reason: "Because it's at the top of your library."
rail:   [("MOOD", [genre, "Mellow"]), ("BEST FOR", ["Walking", "Headphones"])]
```

The design prototype tells a richer story with hand-written copy
("Because you played Vince Maro twice this week", `MOOD: Late
afternoon / Slow / Borough`). The structural code path is correct; it
just needs a real curation model.

Separately, M13 left signing wired (`CODE_SIGNING_ALLOWED = YES`,
`CODE_SIGN_STYLE = Automatic`, team `P63F3C986U`) but the personal
Apple ID flow isn't documented and the project doesn't ship an
entitlements file that survives clean checkouts. M15 closes both.

## Scope

* Panorama curation model + first-pick copy on Home (mac/iPad).
* Real-device deploy flow: signing config, entitlements committed,
  README snippet, and verification that `Cmd+R` to the iPad mini works
  from a fresh checkout.
* Out of scope: full per-album curation database, server-side
  recommendation engine, App Store submission.

## Deliverables

### A. Panorama curation model

1. `Sources/RebornZuneCore/Models/CuratedPick.swift` (new) — a
   `CuratedPick` value type with `eyebrow / title / sub / reason /
   railLines` slots. Drives `HomeScreen.Pick` instead of the
   `library.albums.first`-based ad-hoc construction.
2. `Sources/RebornZuneCore/Catalogs/CuratedPicks.swift` (new) — a
   curated set of 4–5 picks the demo library can map to. Each pick
   has hand-written copy in the design's tone.
3. `Sources/RebornZuneCore/Views/Resonant/Screens/HomeScreen.swift` —
   `picks` computed property pulls from `CuratedPicks` first, falls
   back to the synthesized format when the user's real library has
   no curated match.

### B. Real-device deploy path

4. `RebornZune-iPadOS.entitlements` — verify the auto-generated file
   committed in 72980cc is the canonical one (Hardened Runtime + no
   sandbox flags). Document expected contents in the spec.
5. `README.md` (new section) — "Running on a physical iPad":
   prerequisites (Xcode account, Developer Mode), one-time signing
   handshake, ongoing `xcodebuild -destination "platform=iOS,id=…"`
   command.
6. Verification step: clean checkout on a second account / Mac (or
   simulated via `git clone` to `/tmp`) builds, signs, and runs on
   `JUNDA YIN's iPad` (B2EF2C07-66DA-5CD6-A312-15D0DEFE6144).

### C. Optional polish

7. In-app "change folder" affordance — since demo is the new default
   (M13), users who want their real library need a non-empty-state
   way to invoke the file picker. Easiest: a small mono link in the
   bottom of the artists or settings screen.

## Acceptance criteria

1. Home panorama on Mac and iPad (sim or device) reads with hand-written
   reason / rail copy for the first pick — no `"Because it's at the
   top of your library"` placeholder for the curated path.
2. Visual diff against `Resonant.html` first pick is content-correct
   in addition to layout-correct.
3. Fresh `git clone` → `open RebornZune.xcodeproj` → Cmd+R against the
   plugged-in iPad mini deploys and launches without manual
   project-file editing (signing config already committed and works
   with any developer's Apple ID via Xcode automatic signing).
4. README snippet describes the one-time setup unambiguously enough
   that a teammate could follow it without asking.
5. All four targets continue to build green.

## Out of scope

* Recommendation algorithm — picks remain hand-curated, mapped to
  the demo library by album/artist id.
* App Store / TestFlight pipeline.
* Per-user cloud sync of saved folders or curated lists.
