# M15 — Resonant UI · macOS responsive layout

## Background

M13 introduced `ResonantLayout` (deviceClass × orientation →
`textScale` / `displayFontScale`) and wired it at the iPad app root;
M14 pinned tvOS to an explicit `.expanded .landscape` injection. macOS
was never wired at all: `Apps/macOS/ContentView.swift` injects nothing,
so every view on Mac falls through to the `EnvironmentKey` default of
`.regular .landscape` (`textScale` 1.15, `displayFontScale` 0.92). The
design's display type (150pt HUGE TITLE, 180pt page titles, 42pt
pivots) is calibrated for 1366pt+ surfaces at 1.0 — so on Mac, display
type renders a constant 8% small and body/tag text 15% large relative
to the design.

Worse, the Mac window is freely resizable with no floor
(`RebornZuneMacApp.swift` sets neither default nor minimum size), and
the layout underneath carries fixed-width fossils from the 1440pt
design canvas:

| Site | Hardcoded assumption | Failure mode when window shrinks |
| --- | --- | --- |
| `HomeScreen` | `peek = 173`, rail column `.frame(width: 200)`, dead `canvasWidth = 1440` param | cover + meta + rail row overflows; panels clip mid-glyph |
| `ArtistScreen` | `.frame(width: 420)` column, 240pt / 160pt covers | horizontal overflow |
| `AlbumScreen` | 280pt cover | crowding at narrow widths |
| `NowPlayingScreen` | 260pt / 168pt fixed frames | overflow |
| Browse grids | `.adaptive(minimum: 200)` with fixed minimum | columns squeeze below readability; unbounded proliferation on ultra-wide |

## Decisions (locked for this milestone)

| Area | Decision | Rationale |
| --- | --- | --- |
| Scale model on Mac | **Continuous**, anchored at the 1440pt design width, clamped to [0.75, 1.15] | Mac windows resize continuously; discrete buckets (iPad model) would visibly jump at bucket boundaries mid-drag. |
| Window floor | Minimum size 900 × 600pt, default 1440 × 900pt | Below ~900pt the panorama's three-column bottom strip has no honest layout; a floor beats a broken state. |
| iPad / tvOS | Untouched | iPad keeps discrete buckets; tvOS keeps its explicit `.expanded` injection. Regression-guarded by acceptance criteria. |
| Fixed frames | Made elastic (scaled or maxWidth-bounded), not just scaled-and-clamped | "Responsive" means the layout adapts, not that it shrinks uniformly until it breaks. |

## Scope

* macOS target only.
* `ResonantLayout` gains a continuous-scale path; the iPad bucketing
  API and values stay bit-identical.
* Out of scope: performance pass (planned separately), iPad
  orientation-aware layout (`orientation` remains unconsumed),
  panorama content curation.

## Deliverables

### A. Continuous scale in `ResonantLayout`

1. `Sources/RebornZuneCore/Design/ResonantLayout.swift` — refactor so
   `textScale` / `displayFontScale` are stored values. The existing
   `init(deviceClass:orientation:)` keeps its lookup tables exactly
   (iPad behavior must not change). Add:
   ```
   static func mac(windowSize: CGSize) -> ResonantLayout
   ```
   which derives both scales continuously:
   `displayFontScale = clamp(windowWidth / 1440, 0.75, 1.15)`,
   `textScale = clamp(lerp anchored at 1.0 @ 1440pt, 0.85, 1.1)`.
   Exact curve is the executor's call; the anchor (1.0 @ 1440), the
   clamps, and monotonicity are contractual.
2. `Apps/macOS/ContentView.swift` — wrap the root in a
   `GeometryReader` and inject
   `.environment(\.resonantLayout, .mac(windowSize: proxy.size))`.
   Resize must re-derive the value live (window drag = continuous
   re-layout).

### B. Window sizing

3. `Apps/macOS/RebornZuneMacApp.swift` — set the window default size
   (1440 × 900) and enforce the 900 × 600 floor
   (`.windowResizability(.contentMinSize)` + `.frame(minWidth: 900,
   minHeight: 600)` on the content, or equivalent).

### C. Elastic layout fixes

4. `HomeScreen.swift` — delete the dead `canvasWidth` parameter;
   scale `peek` with `displayFontScale`; the bottom strip's rail
   column width (200pt) scales, and at the window floor the cover /
   meta / rail row must fit without overflow (rail lines truncate
   with `lineLimit(1)` if needed — no mid-glyph clipping).
5. Browse grids (`AlbumsScreen`, `PlaylistsScreen`, `SearchScreen`,
   `ArtistsScreen`) — the `.adaptive(minimum:)` floor scales with the
   layout value instead of sitting at a hard 200pt.
6. Detail screens — `ArtistScreen`'s 420pt column becomes a
   `maxWidth`-bounded elastic column; the 240/160pt covers,
   `AlbumScreen`'s 280pt cover, and `NowPlayingScreen`'s 260/168pt
   frames scale with `displayFontScale` (or migrate to the layout
   value if the executor finds a cleaner token).
7. `PivotNav` / `MiniPlayer` — fixed paddings follow the layout
   scale so chrome rhythm matches the content at all widths.

### D. Tests + evidence

8. `Tests/RebornZuneCoreTests/` — unit tests for
   `ResonantLayout.mac(windowSize:)`: anchor (1440 → 1.0), both clamp
   bounds, monotonicity across the range, and that the iPad bucketed
   init still returns its documented table values.
9. Executor report must include a resize sweep: screenshots of Home,
   Albums, Artist, Album, and Now Playing at window widths
   900 / 1100 / 1440 / 1920 (and the widest the host display allows),
   taken via the existing screenshot harness or `screencapture`,
   demonstrating no overlap, no clipped text, no overflow.

## Acceptance criteria

1. All build commands of record exit 0 (`swift build`, `swift test`,
   and `xcodebuild` for all three app schemes).
2. A fresh launch opens the window at 1440 × 900 and the home tab
   matches the v2 design at scale 1.0 (pivot 56pt top padding, 150pt
   HUGE TITLE, 220pt cover).
3. The window cannot be resized below 900 × 600.
4. Across the 900 → widest resize sweep, every screen in deliverable
   9 shows: no overlapping elements, no mid-glyph clipping, no
   horizontal overflow; type scales monotonically with window width.
5. The dead `canvasWidth` parameter is gone from `HomeScreen`'s API.
6. iPad regression guard: simulator screenshots on iPad mini (A17 Pro)
   and iPad Pro 13-inch (M5) are visually unchanged from pre-M15.
7. tvOS regression guard: `TvResonantApp` still injects
   `.expanded .landscape`; tvOS visuals unchanged.

## Out of scope

* Performance work (TimelineView throttling, tile-wall overdraw,
  per-tile GeometryReader) — separate milestone.
* iPad orientation-aware layouts (`orientation` stays dormant).
* Panorama content curation (was the old M15 scope; dropped).
* Dynamic Type / accessibility text sizes — Resonant type is
  design-locked for now.
