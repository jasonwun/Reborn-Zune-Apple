# M3 — VariableSpanLayout + TileView (no animations yet)

Port the UWP `VariableSizedWrapPanel` + `FluidBitMatrix` packing logic to a SwiftUI
`Layout`, plus a basic `TileView` that renders a single tile with the correct
clipping/aspect. Animations and Metal lighting are M4 and M5; M3 is purely about
geometry and a placeholder visual.

## Deliverables

### 1. Tile span model in `Sources/RebornZuneCore/Views/`

#### `TileSpan.swift`

```swift
public enum TileSpan: Int, Sendable, Hashable {
    case unit = 1   // 1×1
    case medium = 3 // 3×3
    case large = 4  // 4×4
}

public extension TileSpan {
    /// Random span using the same probability distribution as the UWP original:
    /// 87.5% unit, 10% medium, 2.5% large. Uses the provided RNG (defaults to
    /// SystemRandomNumberGenerator).
    static func random<G: RandomNumberGenerator>(using rng: inout G) -> TileSpan
    static func random() -> TileSpan
}
```

The RNG-injected variant is required so tests can use a seeded RNG and assert
exact distributions / sequences.

### 3. Bit-packing helper in `Sources/RebornZuneCore/Views/`

#### `BitMatrix.swift` (internal, not public)

A direct port of the UWP `FluidBitMatrix` packing algorithm, simplified for
SwiftUI's needs:

```swift
struct BitMatrix {
    init(rows: Int, columns: Int)

    /// Try to find an empty region of the given size starting from `startRow`.
    /// Returns the (row, col) of the top-left cell, or nil if no fit.
    mutating func findRegion(startingAt startRow: Int, width: Int, height: Int) -> (row: Int, col: Int)?

    /// Mark the region as occupied.
    mutating func setRegion(row: Int, col: Int, width: Int, height: Int)

    /// The last row index containing any set bit, +1. (i.e., the height of
    /// the "filled" region.)
    var filledRowCount: Int { get }
}
```

Internal storage may use `[UInt64]` packing (matching the UWP impl) OR
`[[Bool]]` if simpler. The `[UInt64]` version is ~10× faster for large grids
but unnecessary for our typical ~200-tile case; pick whichever is cleaner.

### 4. `VariableSpanLayout` in `Sources/RebornZuneCore/Views/`

#### `VariableSpanLayout.swift`

```swift
public struct VariableSpanLayout: Layout {
    public let unitSize: CGFloat   // pixel size of a 1×1 tile (e.g., 70)
    public let spacing: CGFloat    // gap between tiles (default 0)

    public init(unitSize: CGFloat, spacing: CGFloat = 0)

    public func sizeThatFits(
        proposal: ProposedViewSize,
        subviews: Subviews,
        cache: inout Cache
    ) -> CGSize

    public func placeSubviews(
        in bounds: CGRect,
        proposal: ProposedViewSize,
        subviews: Subviews,
        cache: inout Cache
    )

    public typealias Cache = LayoutCache
}

public struct LayoutCache {
    var placements: [(row: Int, col: Int, span: TileSpan)] = []
    var totalRows: Int = 0
}
```

Behavior:

- Read each subview's `TileSpanLayoutKey` to get its span (default `.unit`).
- Compute `cellsPerRow = max(1, floor(proposalWidth / unitSize))`.
- Use `BitMatrix` to pack tiles in row-major order from the top, finding the
  first empty region of `(span.rawValue × span.rawValue)` cells.
- `sizeThatFits` returns `(cellsPerRow * unitSize, filledRows * unitSize)`.
- `placeSubviews` calls each subview's `place(at:proposal:)` with the top-left
  corner of its assigned cell region and a proposal of
  `(span.rawValue * unitSize) × (span.rawValue * unitSize)`.
- Spacing: insets between tiles by `spacing`. (Spec is satisfied even if
  spacing == 0; tests should cover both.)

`makeCache` and `updateCache` should be implemented; the cache is keyed off
the subview count + proposal width so re-layouts are cheap.

### 5. `TileView` in `Sources/RebornZuneCore/Views/`

#### `TileView.swift`

```swift
public struct TileView: View {
    public let image: CGImage?       // nil shows placeholder
    public let span: TileSpan

    public init(image: CGImage?, span: TileSpan)

    public var body: some View
}
```

Visual requirements:
- Renders the image with `.aspectFill` (i.e., fills the tile bounds, crops as
  necessary) — the exact SwiftUI idiom is
  `Image(decorative: cgImage, scale: 1).resizable().aspectRatio(contentMode: .fill)`.
- Black background for tiles with `nil` image.
- Tiles are NOT rounded for M3 (the UWP original has square tiles with a 0.8 px
  black border; reproduce by overlaying a `.border(Color.black, width: 0.8)` or
  similar — exact pixel border isn't critical).
- The view applies `.tileSpan(span)` so it works inside `VariableSpanLayout`
  without callers having to remember to apply the modifier separately.

### 7. Tests in `Tests/RebornZuneCoreTests/`

Note: SwiftUI `Layout` is hard to test without a renderer; we test the underlying
`BitMatrix` directly + the span-distribution + the layout's `sizeThatFits` math
(which is callable without rendering).

#### `BitMatrixTests.swift`
- `testEmptyMatrixFindsTopLeft`: a 10×10 matrix returns (0,0) for a 1×1 region.
- `testSequentialUnitsFillRow`: packing six 1×1 regions into a 6-wide matrix
  gives positions (0,0) through (0,5), and `filledRowCount == 1`.
- `testWrapToNextRow`: in a 4-wide matrix, 5 unit regions: positions
  (0,0),(0,1),(0,2),(0,3),(1,0).
- `testMediumPushesFollowingUnits`: in a 6-wide matrix, [unit, medium, unit, unit]
  yields (0,0), (0,1)-(2,3) for the medium, then (0,4),(0,5) for the units (or
  whatever the deterministic FluidBitMatrix order produces — exact expected
  positions must be computed and asserted).
- `testLargeOverflowsWidth`: a 4×4 region in a 3-wide matrix returns nil
  (cannot fit).
- `testFilledRowCountAfterMixedPlacement`: after mixed placement, filledRowCount
  matches manual count.

#### `TileSpanTests.swift`
- `testDistributionWithSeededRNG`: with a fixed seed, drawing 10000 spans
  yields counts within ±2% of 87.5/10/2.5 expected ratios.
  (Use a `SeededRandomNumberGenerator` test helper — write one if needed.)

#### `VariableSpanLayoutTests.swift`
- `testSizeThatFitsForNoSubviews`: with empty subviews and a 700pt-wide
  proposal at unitSize=70, returns CGSize(width: 700, height: 0).
- `testSizeThatFitsForFourUnitsAtNarrowWidth`: 4 unit subviews at unitSize=70,
  proposal 140pt wide, returns CGSize(700-or-140 width, height = 2 * 70).
  (Width semantics: the layout uses the proposal's width if finite. Spec the
  return precisely in the test.)
- `testCellsPerRowFloorBehavior`: a 175pt proposal at unitSize=70 packs as
  2 cells per row (floor), not 2.5.

(Layout tests construct `VariableSpanLayout` and call `sizeThatFits` and
`placeSubviews` directly. To do that we need `Subviews` instances; SwiftUI does
not let us create those manually. Workaround: test `BitMatrix` directly +
test `VariableSpanLayout.cellsPerRow(for:)` if we expose a helper. If you can't
avoid the renderer dependency cleanly, drop the layout-level tests and rely on
`BitMatrixTests` to cover the packing math — the layout is a thin Layout
adapter over the matrix.)

If layout-level tests prove infeasible to write without rendering, that's fine —
note it in the report and ensure `BitMatrixTests` exhaustively covers the
packing logic (since that's where the actual bugs live). The total test count
must still be ≥ 20 (counting M1+M2 carryover).

## Notes for the executor

- SwiftUI `Layout` protocol docs:
  https://developer.apple.com/documentation/swiftui/layout
- The `Cache` associated type is value-typed and can be `inout`-mutated in
  `sizeThatFits` and `placeSubviews`; use it to avoid recomputing the bit-matrix
  twice.
- SwiftUI calls `sizeThatFits` first (often multiple times with different
  proposals), then `placeSubviews` once with the chosen proposal. The cache must
  be invalidated when subview count changes.
- `Subviews` is a `RandomAccessCollection<LayoutSubview>`. You can iterate,
  index, and read each subview's `LayoutValueKey` via `subview[TileSpanLayoutKey.self]`.
- For the SeededRandomNumberGenerator helper, a `struct` wrapping
  `SystemRandomNumberGenerator` won't work (it isn't seedable). Implement a
  simple LCG or xorshift in the test file:
  ```swift
  struct SeededRNG: RandomNumberGenerator {
      var state: UInt64
      mutating func next() -> UInt64 { state &*= 6364136223846793005; state &+= 1442695040888963407; return state }
  }
  ```
- DO NOT use `Image.resizable().aspectRatio(.fill)` without `.clipped()` on
  the tile — `.fill` overflows by default.
