# M5.7 — Light keyframe panel-scaling + intensity bump

A second VM-recorded UWP reference (`reports/reference/uwp_recording/0502_overview/*`)
revealed M5.6's wash is too narrow and too dim compared to the actual UWP visual.
Two concrete fixes — both small, both high-leverage.

## Reference

`reports/reference/uwp_recording/0502_overview/overview_*.png` — 22 frames spanning
220 s. Key examples:

- `overview_002.png` (t=10 s): warm-orange wash covering ~50% of the wall
- `overview_011.png` (t=100 s): saturated magenta/purple pool covering the right half
- `overview_017.png` (t=160 s): olive-green wash dominating
- `overview_005.png` (t=40 s): subtle olive

Plus dense samples in `0502_warm_peak/`, `0502_purple_peak/`, `0502_flip_window/`.

## Root causes

### 1. Light positions are calibrated for a ~2300×1300 panel

From `Reborn-Zune/TilePage.xaml.cs:106–143`, light keyframe X/Y values:

- Warm: X ∈ [200, 2100], Y ∈ [40, 700]
- Cool: X ∈ [400, 2300], Y ∈ [100, 1200]

That's an X range of ~2100 px assuming the original UWP panel was ~2300 px wide.

On our iPadOS sim (~1180 px wide in native points) and tvOS sim (~1920 px), the
lights spend significant orbit time at X=2100–2300, well outside the visible
panel. When a light's XY projection is off-screen, the visible pixels get only
peripheral Lambertian contribution — the bright pool is invisible.

**Fix**: scale keyframe X/Y proportionally to the actual panel size, using
2300×1300 as the reference. This way the lights orbit *within* the panel
regardless of resolution.

### 2. Intensity 1.3 with strict Lambertian gives a tight pool

Even when the light is in-view, intensity 1.3 with `dot(N,L)` falloff produces
about a 25–30% wall coverage — narrower than the recording's ~50%.

**Fix**: bump `light1Intensity` and `light2Intensity` defaults from 1.3 to 1.8.
This broadens the visible wash without re-introducing M5.5's over-saturation
(which was caused by *missing* `.saturation(0)`, not high intensity).

## Deliverables

### 1. Panel-size scaling in `LightingAnimator`

Modify `Sources/RebornZuneCore/Views/LightingAnimator.swift`:

Add a constant for the reference panel size:

```swift
public extension LightingAnimator {
    /// The panel dimensions the UWP source's keyframe X/Y coordinates were
    /// calibrated for. Light positions are scaled proportionally to the
    /// actual panel size at render time.
    static let referencePanelSize: CGSize = CGSize(width: 2300, height: 1300)
}
```

Modify `parameters(at:panelSize:)` so it scales the interpolated XY positions
from `referencePanelSize` to the actual `panelSize`:

```swift
public func parameters(at time: TimeInterval, panelSize: CGSize) -> LightingParameters {
    // ... existing keyframe interpolation gives p_warm, p_cool ...

    let scaleX = Float(panelSize.width / Self.referencePanelSize.width)
    let scaleY = Float(panelSize.height / Self.referencePanelSize.height)

    let scaledWarmPos = SIMD3<Float>(p_warm.x * scaleX, p_warm.y * scaleY, p_warm.z)
    let scaledCoolPos = SIMD3<Float>(p_cool.x * scaleX, p_cool.y * scaleY, p_cool.z)

    return LightingParameters(
        panelSize: panelSize,
        light1Position: scaledWarmPos,
        light1Color: c_warm,
        light2Position: scaledCoolPos,
        light2Color: c_cool,
        // intensity + ambient defaults from LightingParameters init
    )
}
```

Z is NOT scaled (it represents light depth, panel-independent).

### 2. Default intensity bump

Modify `Sources/RebornZuneCore/Views/LightingParameters.swift`:

```swift
public init(
    panelSize: CGSize,
    light1Position: SIMD3<Float>,
    light1Color: SIMD3<Float>,
    light1Intensity: Float = 1.8,        // was 1.3
    light2Position: SIMD3<Float>,
    light2Color: SIMD3<Float>,
    light2Intensity: Float = 1.8,        // was 1.3
    ambientColor: SIMD3<Float> = SIMD3<Float>(0.165, 0.165, 0.165)
)
```

Ambient stays unchanged (matches UWP `#d3d3d3 * 0.20`).

## Notes for executor

- A test that hard-codes a "warm light X at t=0" needs the panel size as input;
  if you previously asserted `position.x == 200`, change to assert
  `position.x == 200 * Float(panelSize.width / 2300)` or pass
  `panelSize = CGSize(2300, 1300)` to keep the literal value.
- Sub-pixel rounding from float arithmetic might produce e.g. 100.0001 — use
  `XCTAssertEqual(..., accuracy: 0.001)` for the ratio assertion.
- The user is watching tvOS at 1920×1080 (visible region of the sim).
  scaleX ≈ 1920/2300 = 0.835. Warm light X range becomes ~167–1754. Most of
  the orbit will now be on-screen.
- For iPad Pro 13" sim (~1180 px wide native), scaleX ≈ 0.51. Warm orbit
  becomes ~102–1071. All on-screen. Pool will be more visible than before.
