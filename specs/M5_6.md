# M5.6 — Two-layer architecture + Lambertian lighting (UWP-recording parity)

The user supplied a recording of the original UWP `TilePage` (now saved at
`reports/reference/uwp_recording/frame_*.png`). It revealed that M5.5's
"saturated colored wash on bright tiles" target is **wrong** — the real UWP
effect is "subtle warm pool over a fully desaturated grayscale tile wall."

## Root cause from the original UWP source

`TilePage.xaml` lines 34–38:
```xml
<Border HorizontalAlignment="Stretch" VerticalAlignment="Stretch">
    <Border.Background>
        <media:BackdropSaturationBrush Saturation="0" />
    </Border.Background>
</Border>
```

The original architecture is **two layers**:

1. **Bottom**: `VariableSizedWrapPanel` rendering colored album-art tiles
2. **Top**: A full-cover Border with a `BackdropSaturationBrush(Saturation=0)` —
   this is a backdrop-effect brush that captures everything rendered behind it,
   desaturates to grayscale, and re-renders. Effectively it's a transparent
   overlay that "absorbs" the color underneath.

The XAML composition lights target `_root = tilesPanel` (the parent Grid
containing BOTH the wrap panel and the saturation overlay), so they
illuminate the rendered grayscale output, not the original tiles.

Net visual: monochrome album art lit by warm/cool point lights and a gray ambient.

We've been doing it wrong: multiplying colored lights into colored synthetic
tiles. The result was "muddy colorful wash everywhere." Fix below.

## Deliverables

### 1. Two-layer rendering in `TileWallView`

Modify `Sources/RebornZuneCore/Views/TileWallView.swift`:

```swift
public var body: some View {
    let content = VariableSpanLayout(unitSize: unitSize) {
        ForEach(...) { TileView(...) }
    }
    .saturation(0)  // ← NEW: grayscale conversion before lighting

    if let animator = lightingAnimator {
        content.modifier(LightingModifier(animator: animator))
    } else {
        content
    }
}
```

The `.saturation(0)` modifier is SwiftUI's exact equivalent of
`BackdropSaturationBrush(Saturation=0)` — it strips chrominance and keeps
luminance. The lighting shader then receives a grayscale `currentColor`
and tints it warm/cool.

Apply the same change to `TileWallView.staticSnapshot(...)`.

### 2. Lambertian diffuse lighting in the Metal shader

Replace the gentle quadratic falloff in `Sources/RebornZuneCore/Views/LightingShader.metal`
with proper Lambertian diffuse based on the light's Z-axis position relative
to the tile wall (which is at Z=0).

New body:

```metal
[[stitchable]]
half4 zuneLighting(
    float2  position,
    half4   currentColor,
    float2  panelSize,
    float3  light1Pos,
    float3  light1Color,
    float3  light2Pos,
    float3  light2Color,
    float3  ambientColor,
    float   light1Intensity,
    float   light2Intensity
) {
    float3 pixelPos = float3(position.xy, 0.0);
    float3 normal = float3(0.0, 0.0, 1.0);

    // Light 1 — Lambertian diffuse contribution
    float3 light1Dir = normalize(light1Pos - pixelPos);
    float diff1 = max(0.0, dot(normal, light1Dir));
    float3 contrib1 = light1Color * light1Intensity * diff1;

    // Light 2 — Lambertian diffuse contribution
    float3 light2Dir = normalize(light2Pos - pixelPos);
    float diff2 = max(0.0, dot(normal, light2Dir));
    float3 contrib2 = light2Color * light2Intensity * diff2;

    float3 totalLight = ambientColor + contrib1 + contrib2;

    half3 lit = half3(currentColor.rgb) * half3(totalLight);
    return half4(lit, currentColor.a);
}
```

Note: the `attenuationScale` parameter is **removed** from the shader's
signature. The Z-component of the light direction (i.e. `300/sqrt(d²+300²)`
where `d` is the XY distance from the light's projection to the pixel) gives
the natural pool falloff — no separate attenuation term needed.

Light positions remain at Z=300 (matching the UWP source's `lightDepth`).

## Notes for executor

- SwiftUI's `.saturation(amount:)` takes a Double 0–1 (0 = grayscale, 1 = full color).
  Apply it to the layout view, NOT to individual `TileView`s — applying once at the
  parent is cheaper and matches the UWP layered architecture.
- The `.saturation(0)` modifier must be applied **before** `.modifier(LightingModifier())`.
  In SwiftUI's modifier chain semantics, this puts saturation lower in the render
  pipeline, so the lighting shader's `currentColor` reads the desaturated pixel.
- Lambertian dot product gives a value in [0, 1]. With normal=(0,0,1) and
  light position with Z>0, dot(N, L) is just the Z-component of the normalized
  light direction = `lz / sqrt(dx² + dy² + lz²)`. This is naturally 1.0 directly
  under the light's XY projection and falls off with XY distance.
- DO NOT introduce a separate distance attenuation factor on top of Lambertian.
  The dot product alone gives the pool effect we want.
- DO NOT try to also blend a sliver of the original color back in. M5.6's
  whole point is parity with the UWP recording, and that recording has no
  visible color leakage under the lighting.
- The animation timing and keyframes are unchanged from M5/M5.5. Only the per-pixel
  shading model and the saturation pre-step are new.
