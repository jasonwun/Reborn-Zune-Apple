# M4 — Metal lighting shader (PointLights parity)

The pixel-level core of TilePage parity. Implement two animated point lights +
ambient lighting as a Metal fragment shader, applied to the tile wall via
SwiftUI's `.colorEffect` modifier. Light positions and colors animate through
a 120-second keyframe loop matching the UWP original's timing and palette.

## Reference (UWP original)

Source: `/Users/yjd/Documents/Reborn-Zune/Reborn-Zune/TilePage.xaml.cs`,
`TileRoot_Loaded` method.

Key parameters from the original:
- `lightDepth = 200` (Z position of both lights, in panel-pixel space)
- `animationDelay = 600 ms` (delay before lights begin orbiting)
- `animationDuration = 120 s` (full loop)
- 7 position keyframes per light (start, 16%, 32%, 48%, 64%, 80%, end)
- 6 color keyframes per light
- Ambient: color `#d3d3d3`, intensity `0.20`

## Deliverables

### 1. Metal shader source

#### `Sources/RebornZuneCore/Views/LightingShader.metal`

A `[[stitchable]]` color-effect fragment shader compatible with SwiftUI's
`Shader.colorEffect(_:)`:

```metal
#include <metal_stdlib>
using namespace metal;

[[stitchable]]
half4 zuneLighting(
    float2  position,            // pixel position in the layer's coord space
    half4   currentColor,        // sampled color at this pixel
    float2  panelSize,           // total panel size in pixels (for normalization)
    float3  light1Pos,           // current animated position of light 1
    float3  light1Color,         // current animated color of light 1 (RGB 0..1)
    float3  light2Pos,           // current animated position of light 2
    float3  light2Color,         // current animated color of light 2
    float3  ambientColor,        // ambient color (0..1) including intensity scaling
    float   light1Intensity,     // typically 1.3
    float   light2Intensity,     // typically 1.3
    float   attenuationScale     // distance-falloff scale; tune for visual parity
);
```

Behavior — port of XAML PointLight semantics, simplified:

```
For each pixel at (position.x, position.y, 0):
    For each point light:
        d = distance(pixelPos, lightPos)
        falloff = 1 / (1 + d² * attenuationScale)
        contribution = lightColor * intensity * falloff
    totalLight = ambientColor + light1.contribution + light2.contribution
    output.rgb = currentColor.rgb * totalLight
    output.a   = currentColor.a
```

The XAML PointLight's true attenuation formula is
`1 / (constant + linear*d + quadratic*d²)` with all-1.0 default coefficients,
but values get washed-out fast at panel scale. We replace with `1 / (1 + d² * scale)`
where `scale` is tuned (recommended start: `1e-6` so a 1000-pixel distance gives
falloff ≈ 0.5). The exact value is a tuning parameter; the spec does not
require a specific number, only that the result resembles the reference UWP
visual at typical panel sizes (1920×1080).

### 3. Keyframe animation engine

#### `Sources/RebornZuneCore/Views/LightingKeyframes.swift`

Pure Swift, no Metal/SwiftUI imports — testable in isolation:

```swift
public struct LightKeyframes: Equatable, Sendable {
    public struct PositionKey: Equatable, Sendable {
        public let progress: Double         // 0...1
        public let position: SIMD3<Float>
    }
    public struct ColorKey: Equatable, Sendable {
        public let progress: Double         // 0...1
        public let color: SIMD3<Float>      // RGB 0..1
    }

    public let positions: [PositionKey]     // monotonically increasing progress, must include 0 and 1
    public let colors: [ColorKey]           // same constraint
}

public extension LightKeyframes {
    /// Linearly interpolate position at the given normalized time (0...1).
    func position(at progress: Double) -> SIMD3<Float>
    /// Linearly interpolate color at the given normalized time (0...1).
    func color(at progress: Double) -> SIMD3<Float>
}

public enum LightingPalette {
    /// First light: warm orange/green/rust palette from the UWP original.
    public static let warm: LightKeyframes
    /// Second light: purple/blue/green palette from the UWP original.
    public static let cool: LightKeyframes
}
```

The two preset `LightKeyframes` values must contain exactly the 7 position keys
and 6 color keys from the UWP source, with the same RGB values converted from
hex to SIMD3<Float> (component / 255).

Hex → RGB reference (warm light):
- `#865c2a` → (0.525, 0.361, 0.165)
- `#955a21` → (0.584, 0.353, 0.129)
- `#6c891b` → (0.424, 0.537, 0.106)
- `#62962c` → (0.384, 0.588, 0.173)
- `#6c401b` → (0.424, 0.251, 0.106)

Hex → RGB reference (cool light):

### 4. Animator that produces `LightingParameters` over time

#### `Sources/RebornZuneCore/Views/LightingAnimator.swift`

```swift
public struct LightingAnimator: Sendable {
    public let warm: LightKeyframes      // light 1
    public let cool: LightKeyframes      // light 2
    public let cycleDuration: TimeInterval  // default 120
    public let warmDelay: TimeInterval      // default 0.6 (matches animationDelay 600ms)

    public init(
        warm: LightKeyframes = .warm,
        cool: LightKeyframes = .cool,
        cycleDuration: TimeInterval = 120,
        warmDelay: TimeInterval = 0.6
    )

    /// Produce a `LightingParameters` value for the given absolute time
    /// (e.g., `Date.timeIntervalSinceReferenceDate` or any monotonic clock).
    /// Time is reduced modulo cycleDuration internally.
    public func parameters(at time: TimeInterval, panelSize: CGSize) -> LightingParameters
}
```

Behavior:
- `progress = ((time - warmDelay).truncatingRemainder(dividingBy: cycleDuration)) / cycleDuration`
  for the first light; `progress = (time.truncatingRemainder(dividingBy: cycleDuration)) / cycleDuration`
  for the second light. (The UWP code applies `animationDelay` only to the warm
  light's animation start. Verify by re-reading `TilePage.xaml.cs`.)
- For times below `warmDelay`, the warm light should sit at its `progress=0`
  position/color (i.e., `negative progress → clamp to 0`, not wrap).
- Cool light has no delay; starts animating immediately.

### 5. SwiftUI `LightingModifier` view modifier

#### `Sources/RebornZuneCore/Views/LightingModifier.swift`

```swift
public struct LightingModifier: ViewModifier {
    public let animator: LightingAnimator

    public init(animator: LightingAnimator = LightingAnimator())

    public func body(content: Content) -> some View
}

public extension View {
    /// Apply the Zune-style two-light + ambient composition lighting effect
    /// to this view, animating over the configured cycle.
    func zuneLighting(animator: LightingAnimator = LightingAnimator()) -> some View
}
```

Implementation:
- Use `TimelineView(.animation)` to drive frame updates.
- Read `GeometryReader` (or `geometry.size` from a `GeometryReader { geo in ... }`)
  to obtain the panel size for `LightingParameters`.
- Compose the shader via `ShaderLibrary.bundle(.module).zuneLighting` — the
  Metal source must be in `Sources/RebornZuneCore/Views/` and SwiftPM will
  compile it into the module's metallib automatically.
- Apply via `.colorEffect(Shader(function: shaderFn, arguments: [...]))`.

Performance note: argument list ordering must match the Metal shader signature.

## Out of scope for M4

- Tile flip animation (M5)
- Staggered fade-in waves (M5)
- Audio playback / Now Playing (M6)
- Tuning the `attenuationScale` for "perfect" visual parity — that requires running
  on-device and eyeballing against the UWP reference. Pick a sensible default
  value; later milestones (M7+) can fine-tune.
- Pixel-level snapshot tests of shader output — too brittle and require GPU.

## Notes for the executor

- SwiftUI Shader docs: https://developer.apple.com/documentation/swiftui/shader
- The `[[stitchable]]` attribute is required for `colorEffect`/`layerEffect` shaders.
- `ShaderLibrary.bundle(.module).zuneLighting` is the modern way to reference a
  shader compiled into a Swift package's bundle. The function name in MSL must
  exactly match the property name accessed in Swift (`zuneLighting` →
  `zuneLighting`).
- Argument ordering in `Shader(function:arguments:)` MUST match the MSL
  parameter order after `position` and `currentColor`. (SwiftUI passes those
  two implicitly; you supply the rest in order.)
- For `SIMD3<Float>` shader arguments, use `.float3(simd)` in
  `Shader.Argument`.
- For `CGSize`, use `.float2(SIMD2<Float>(Float(size.width), Float(size.height)))`.
- The `TimelineView(.animation)` schedule produces ~60 fps on most displays,
  reduced under low-power. That's fine — the shader is cheap.
- DO NOT animate `LightingParameters` via SwiftUI `withAnimation` — the
  TimelineView is the animation source. Mixing the two double-animates and
  causes jitter.
- If you can't get SwiftPM to auto-compile the .metal file, fall back to
  declaring it as `process` resource and loading via `MTLDevice` manually —
  but this should not be necessary on Swift 6+.
