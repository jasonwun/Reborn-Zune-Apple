# M5.5 — Visual tuning pass (reference-driven)

A small, focused milestone to bring the rendered output closer to the original
Zune references the user supplied. No new architecture; only parameter tuning,
better synthetic content, and one new `TileSpan` case.

## Reference images

The user supplied two Zune PC client screenshots, saved at:

- `reports/reference/zune_original/zune_pc_01.jpg` — warm-orange dominated phase (Stevie Ray Vaughan / Texas Flood)
- `reports/reference/zune_original/zune_pc_02.jpg` — yellow-olive warm + cool-pink corner phase (P!nk / Can't Take Me Home)

These define the visual target. The executor and evaluator must Read both
files and reference them in their reports.

## Observed gaps in current output

From comparing M5 simulator screenshots against the references:

1. **Synthetic tile content is too saturated/bright.** Rainbow gradients
   leave no headroom for multiplicative lighting to express. Real album
   art (Zune references) is mostly dark/medium-tone, which is why the
   warm wash reads dramatically.
2. **Too few tiles.** 64 synthetic tiles fill only the upper third of a
   1280×720 panel. Zune fills the entire wall edge-to-edge.
3. **Span distribution is wrong.** We have only `.unit (1)`, `.medium (3)`,
   `.large (4)`. Zune visibly uses 2×2 tiles as the most common "medium"
   size. We're missing it.
4. **Lighting parameters are too soft.** Ambient at 0.21 with intensity 1.3
   produces a desaturated mix. Zune's wash is dramatically saturated and
   broad.

## Deliverables

### 1. Add `.small = 2` to `TileSpan`

Modify `Sources/RebornZuneCore/Views/TileSpan.swift`:

```swift
public enum TileSpan: Int, Sendable, Hashable {
    case unit = 1     // 1×1
    case small = 2    // 2×2  ← NEW
    case medium = 3   // 3×3
    case large = 4    // 4×4
}
```

Update `TileSpan.random(using:)` probability distribution to match the
Zune density visible in the references:

| Span   | Probability | Reasoning |
| ---    | ---         | --- |
| unit   | 70%         | dominant; 1×1 small album art |
| small  | 20%         | the most common "feature" tile |
| medium | 8%          | a few prominent albums |
| large  | 2%          | very rare |

### 2. Replace `SyntheticTiles` with album-art-like dark gradients

Modify `Sources/RebornZuneCore/Views/SyntheticTiles.swift`:

- Replace the existing rainbow gradient generator with one that produces
  **dark, muted gradients in the brightness range 0.05–0.45**.
- Color palettes to draw from (pseudo-random selection per tile):
  - charcoal-to-deep-blue
  - sepia-to-dark-brown
  - black-to-deep-purple
  - black-to-forest-green
  - dark-gray-to-rust
  - black-to-deep-teal
  - charcoal-to-burgundy
- Each gradient is a 2-color radial or linear gradient, randomly oriented.
- Keep the deterministic-by-seed property: same seed produces same tiles.
- Keep at least 2–3 image variants per tile so flip cycling has variety.

The public API does NOT change — `SyntheticTiles.sample(seed:count:)` retains
the same signature. Default count bumps from 64 → 250.

### 3. Tune lighting parameters

Modify `Sources/RebornZuneCore/Views/LightingParameters.swift`:

Update default values in the public initializer:

```swift
public init(
    panelSize: CGSize,
    light1Position: SIMD3<Float>,
    light1Color: SIMD3<Float>,
    light1Intensity: Float = 2.0,        // was 1.3
    light2Position: SIMD3<Float>,
    light2Color: SIMD3<Float>,
    light2Intensity: Float = 2.0,        // was 1.3
    ambientColor: SIMD3<Float> = SIMD3<Float>(0.10, 0.10, 0.10),  // was (0.21, 0.21, 0.21)
    attenuationScale: Float = 8.0e-7     // was 1.0e-6 — slightly broader falloff
)
```

These three values together let the lights dominate over ambient, producing
a saturated wash like the references. Existing tests that hard-coded
intensity 1.3 / ambient 0.21 / attenuation 1.0e-6 must be updated to the
new defaults OR rewritten to construct LightingParameters explicitly with
the old values to preserve the test's intent.

## Notes for executor

- This is a SHORT pass. Total source-code changes should be under 100 lines
  excluding gradient palette data.
- Don't over-tune. If the first set of parameter changes already looks close
  to the references, stop — further tuning risks overshoot.
- The `attenuationScale = 8e-7` value: at a 1000 px distance, falloff =
  1/(1 + 1e6 * 8e-7) = 1/1.8 ≈ 0.56. So the wash extends well beyond 1000 px
  with significant brightness, matching Zune's broad coverage.
- For `SyntheticTiles` gradient generation, use `CGGradient` with two color
  stops and `CGContext.drawLinearGradient` or `drawRadialGradient`. Keep tile
  size at 256×256 — small enough to be cheap, large enough to look smooth.
- DO NOT introduce bright accent colors in the gradients. The whole point is
  dark headroom. If a palette feels too dim, add SLIGHT variation (one stop
  at 0.1, the other at 0.4) rather than brightening.
