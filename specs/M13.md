# M13 — Resonant UI · iPad visual parity (design v2) + responsive layout system

## Background

After M12 landed v2 parity on macOS, the iPad shell still rendered the
v1 mock iOS status bar and used Mac-tuned type sizes calibrated for
1366pt surfaces. The design v2 bundle's iPad CSS overrides
(`[data-platform="ipad"] …` in `styles.css`) make four kinds of
changes:

| Group | Design v2 spec | Status pre-M13 |
| --- | --- | --- |
| Chrome | No status bar (only home indicator), pure black `--paper`, pivot padding-top 48 | Mock status bar present, warm paper, pivot 28 |
| Touch sizes | Mini-player art 52, play 48, ctrl 32; scrubber bar 3pt; track-row vpad 18 | Same as Mac (44 / 38 / 22 / 2 / 14) |
| Type | Display 150pt / pivots 42pt / page titles 180pt are calibrated for ≥1366pt surfaces | Identical to Mac; overwhelms iPad mini |
| Library default | First-run shows folder picker | Same; friction every cold launch |

M13 closes the parity gap **and** introduces the responsive layout
machinery iPad needs to span mini → Pro 13 cleanly. macOS and tvOS
inherit anything universal.

## Scope

* iPad target (M5 / 11 / 13 / Air / Pro 11 / Pro 13) — both orientations.
* Universal helpers (`ResonantLayout`, hit-area, rotator) shared with
  Mac and tvOS where the env value's default lands them at 1.0×.
* Out of scope: iPhone (target device family stays = 2), tvOS visual
  refresh (M14), curated content copy (M15).

## Deliverables

### A. iPad chrome (drop the mock status bar)

1. `Sources/RebornZuneCore/Views/Resonant/IPadShell.swift` — delete
   `statusBar`, keep only `homeIndicator` (140 × 5pt centered, bottom
   8pt). Per the design call recorded in `ipad-shell.jsx`.
2. `Apps/iPadOS/ContentView.swift` — drop `.padding(.top, 32)` (status
   bar gutter), add `.statusBarHidden(true)` so the real iOS status
   bar doesn't reappear on top.

### B. Color ramp

3. `Sources/RebornZuneCore/Design/ResonantColors.swift` — unify `paper /
   paper2 / paper3` on Mac's warm near-black (`#0E0D0A / #161512 /
   #1F1D19`) across mac/iPad/tvOS. This *deviates* from the design's
   `#000000` spec for OLED platforms (user preference: warmer ramp
   reads gentler against the magenta accents).

### C. Touch sizes

4. `Sources/RebornZuneCore/Views/Resonant/MiniPlayer.swift` — scrubber
   bar height switches on `isTouch` (2pt mac, 3pt iPad).
5. `Sources/RebornZuneCore/Views/Resonant/Screens/AlbumScreen.swift` —
   `TrackRow` vertical padding switches on `#if os(macOS)` (14pt mac,
   18pt elsewhere).

### D. Library default

6. `Apps/iPadOS/ContentView.swift` — when no env override and no saved
   folder, fall through to `ResonantDemoLibrary.makeMusic()` instead of
   the empty-state picker. Real folder pick still writes
   `LibraryFolderStore` for subsequent launches.
7. `Apps/tvOS/ContentView.swift` — same fallback when neither
   `REBORN_ZUNE_DEBUG_DEMO_LIBRARY` nor bundled `UserMusic` exist.

### E. Responsive layout system (the structural piece)

8. `Sources/RebornZuneCore/Design/ResonantLayout.swift` (new) — public
   Sendable struct with:
   ```
   ResonantLayout {
     deviceClass: .compact | .regular | .expanded   // min(w,h) bucketed
     orientation: .portrait | .landscape             // w vs h
     textScale: 1.0 / 1.15 / 1.25                    // body / mono / tag
     displayFontScale: 0.7 / 0.92 / 1.0              // headlines + gaps
   }
   ```
   Published as `\.resonantLayout` via `GeometryReader` at the iPad app
   root. Mac and tvOS hit the default (`.regular .landscape`, 1.0×) and
   don't vary.
9. `Sources/RebornZuneCore/Design/ResonantFonts.swift` — `resonantTag`
   now returns `some View` and reads `\.resonantLayout` to multiply
   size + tracking by `textScale`. New chainable
   `.resonantScaledFont(_:weight:design:tracking:)` modifier covers
   non-tag `.font(.system(size: 10/11, …))` spots in MiniPlayer
   meta / scrubber / UP NEXT and `TrackRow` number / duration and
   `FilterChipRow` chip text.
10. `HomeScreen.swift` — title block reads `displayFontScale`: HUGE
    TITLE size, tracking, sub-line `.offset(y:)` (the 150 × 0.86 = 129
    relationship), eyebrow negative padding, *and* the cover/strip
    height + anchor all scale together so the visual hierarchy
    survives shrinking. `PivotNav` + `AlbumsScreen` / `PlaylistsScreen`
    / `ArtistsScreen` page titles and gap chains scale the same way.
11. All 4 tabs share a single vertical rhythm: chrome→eyebrow ≈ 20pt
    × scale, eyebrow→title ≈ 12pt × scale, screen-top inset 8pt ×
    scale, sort-row 4pt top / 20pt bottom × scale.

### F. Universal hit-area fix

12. `FilterChipRow`, `primaryButton`, `secondaryButton`, `PivotButton`,
    and the panorama `arrowButton` move their `.background` /
    `.overlay` inside the `Button` label and add
    `.contentShape(Rectangle())` so `.buttonStyle(.plain)` treats the
    whole pill as hit-testable instead of just the rendered glyph.

### G. MiniPlayer rotator (universal)

13. The "Now Playing ↔ Up Next" cross-fade is owned by `startRotator()`:
    `withAnimation(700ms cubic-bezier)` for the simultaneous
    `exiting`/`mode` writes, `withTransaction { disablesAnimations = true }`
    for the parked snap. `\.onChange(of: upNext?.id)` re-arms when the
    next track flips without a play-state transition.

### H. iPad-only target family

14. iPad target's `TARGETED_DEVICE_FAMILY = 2` (already set;
    `CODE_SIGNING_ALLOWED` flipped to YES at the project level so
    automatic signing actually takes effect when a real device is
    plugged in).

## Acceptance criteria

1. `xcodebuild -project RebornZune.xcodeproj -scheme RebornZune-iPadOS -destination "platform=iOS Simulator,name=iPad Pro 13-inch (M5)" build` exits 0.
2. Same build succeeds against `name=iPad mini (A17 Pro)`.
3. On iPad Pro 13" landscape (1366 × 1024) the home tab looks
   structurally identical to `Resonant - iPad.html` rendered at the
   same viewport — pivots, eyebrow, HUGE TITLE, cover/meta/rail,
   mini-player, home indicator all in place. Remaining content
   diffs (cover variant, reason copy) are M15.
4. On iPad mini portrait or landscape no element overlaps the cover,
   the pivot row doesn't dominate the screen, and small text reads at
   the same physical size as it does on a Mac window.
5. Click anywhere inside any `Button(...).buttonStyle(.plain)` chrome
   on every tab triggers the action (chips, CTAs, arrows, pivots).
6. With no env vars and no saved folder, iPad / tvOS first-launch
   shows the demo library directly — no empty-state picker.
7. Building all three app targets continues to exit 0; tvOS visuals
   are unchanged.

## Out of scope

* OLED true-black per design spec (user prefers warm; documented).
* iPhone (target device family locked to iPad).
* Curated panorama copy + first-album visual variants — M15.
* tvOS visual refresh (vocab, font 56, brand removal) — M14.
