# M5.8 — Wall-level flip coordinator + darker baseline

User feedback after observing M5.7 in a live tvOS sim revealed three structural
gaps from the UWP recording:

1. **Tiles look colorful** — even though `.saturation(0)` IS applied (verified
   in source), the lighting at intensity 1.8 + ambient 0.165 saturates so much
   of the wall that the desaturation isn't observable. The user wants to see
   that the underlying tiles are grayscale.
2. **Ambient is too bright** — in the UWP recording, the majority of the wall
   is dark, only the light *point* is visibly bright. We have ambient bleeding
   colored light across the entire wall.
3. **Flip animation is per-tile, not wall-level** — `TileView` has its own 5 s
   timer with per-tile `initialDelay` stagger, so with 250 tiles the wall
   produces ~50 flips/second. The UWP source (`TilePage.xaml.cs:202-220`)
   flips ONE random tile every 5 s. This is a major behavioral mismatch.

## Reference

- UWP source for flip cadence: `Reborn-Zune/TilePage.xaml.cs:202-220`
  ```csharp
  TimeSpan period = TimeSpan.FromSeconds(5);
  ThreadPoolTimer PeriodicTimer = ThreadPoolTimer.CreatePeriodicTimer(async (source) =>
  {
      Random rnd = new Random();
      await Dispatcher.RunAsync(CoreDispatcherPriority.High, () =>
      {
          int imgSouceIdx = rnd.Next(TileVM.BitmapList.Count);
          int tileIdx = rnd.Next((int)(TileVM.Tiles.Count * 0.8));
          var imgSource = TileVM.BitmapList[imgSouceIdx];
          var tile = TileVM.Tiles[tileIdx] as Tile;
          tile.UpdateThumbnail(_compositor, imgSource);
      });
  }, period);
  ```
- Visual reference for "majority dark, point of light visible":
  `reports/reference/uwp_recording/0502_overview/overview_011.png` —
  the left half of the wall is nearly black; only the right ~40% glows purple.

## Deliverables

### 1. Drop per-tile flip timer; introduce a wall-level flip coordinator

Modify `Sources/RebornZuneCore/Views/TileView.swift`:

- **Remove** the `flipPeriod`, `flipDuration`, `initialDelay` parameters and
  the internal `Task`-driven timer. The view becomes:

```swift
public struct TileView: View {
    public let images: [CGImage?]
    public let span: TileSpan
    /// External flip pulse — incrementing this Int triggers one flip animation.
    /// Wired by `TileWallView`'s wall-level coordinator.
    public let flipPulse: Int
    public let flipDuration: TimeInterval

    public init(
        images: [CGImage?],
        span: TileSpan,
        flipPulse: Int = 0,
        flipDuration: TimeInterval = 1.2
    )
}
```

- The view internally tracks `lastSeenPulse: Int`; when `flipPulse` changes,
  it runs `runFlip()` once.
- The flip animation itself (rotate 0→90, fade out, image swap, rotate 270→360,
  fade in) is unchanged — this is M5/UWP-faithful.
- The `images.count <= 1` guard stays.

### 2. Add `TileFlipCoordinator` in `Sources/RebornZuneCore/Views/`

#### `TileFlipCoordinator.swift`

```swift
import Foundation
import Observation

@MainActor
@Observable
public final class TileFlipCoordinator {
    /// The tile index (into the wall's tile array) that should flip next.
    /// Mutates from -1 → some index. Children watch `flipPulses[i]` to detect
    /// "their turn".
    public private(set) var flipPulses: [Int] = []

    public init() {}

    /// Starts the flip scheduler. Picks one random tile every `period` seconds
    /// from the first 80% of `tileCount` (matches UWP behavior). Increments
    /// the chosen index's entry in `flipPulses` to signal a flip.
    public func start(tileCount: Int, period: TimeInterval = 5.0)

    public func stop()
}
```

Implementation:
- `start` initializes `flipPulses = Array(repeating: 0, count: tileCount)`.
- A `Task` loops: `Task.sleep(period)` then increment a random index in
  `flipPulses[0..<eligibleCount]` where `eligibleCount = max(1, Int(Double(tileCount) * 0.8))`.
- Use `SystemRandomNumberGenerator` (no seed needed — flip cadence isn't
  deterministic).
- `stop` cancels the task.
- Idempotent: calling `start` twice cancels the previous task.

### 3. Wire the coordinator into `TileWallView`

Modify `Sources/RebornZuneCore/Views/TileWallView.swift`:

- Add a `@State private var flipCoordinator = TileFlipCoordinator()` (note:
  `@State` of a reference type pins the instance for the view's lifetime).
- In `onAppear`, call `flipCoordinator.start(tileCount: tiles.count)`.
- In `onDisappear`, call `flipCoordinator.stop()`.
- In the `ForEach`, pass `flipPulse: flipCoordinator.flipPulses[safe: index] ?? 0`
  to each `TileView`. Drop the `initialDelay` calculation.
- Drop `flipPeriod` and `flipDuration` overrides from the call site (use
  TileView defaults).

### 4. Tune lighting for darker baseline + focused pool

Modify `Sources/RebornZuneCore/Views/LightingParameters.swift`:

- `ambientColor` default: `SIMD3<Float>(0.165, 0.165, 0.165)` → `SIMD3<Float>(0.05, 0.05, 0.05)`
- `light1Intensity` default: `1.8` → stays `1.8` (peak brightness needed for
  visible pool; lowering ambient is what creates the dark majority)
- `light2Intensity` default: `1.8` → stays `1.8`

The intensity stays high so peaks read as bright; dropping ambient means
non-pool areas drop to near-black.

If after capturing M5.8 the wall is too dark overall (no tile detail visible
even at peak), the executor may iterate ONCE within these ranges:

- `ambientColor` scalar: 0.03–0.10
- `light1Intensity`/`light2Intensity`: 1.5–2.0

Document the iteration in the report.

## Out of scope

- Changing keyframe positions or palette
- Changing entry-wave animation
- Changing flip animation timing within a single flip (still 1.2 s, 0→90/270→360)
- Audio (M6)

## Notes for executor

- The wall-level flip coordinator is the most important behavioral fix. Get
  this right.
- For `TileView`, removing `initialDelay` is intentional — the wall's timer
  produces stagger by picking different tiles each tick.
- The `flipPulse: Int` parameter changes when the wall wants this tile to
  flip. The TileView watches via `.onChange(of: flipPulse)`. In
  Swift 5.9+ / iOS 17+, the modern `.onChange` form is
  `.onChange(of: flipPulse) { _, _ in ... }`.
- For `@State private var flipCoordinator = TileFlipCoordinator()`: make the
  coordinator a class (not struct), and use `@State` to hold it. SwiftUI's
  `@State` keeps the same instance across re-renders.
- Don't try to hold `TileFlipCoordinator` as a `@StateObject` — that's
  Combine-era; modern equivalent is `@State` with `@Observable`.
- For the env-var debug hook: add to `DefaultContent` something like:
  ```swift
  let lighting = ProcessInfo.processInfo.environment["REBORN_ZUNE_DEBUG_NO_LIGHTING"] == "1"
              ? nil
              : LightingAnimator()
  TileWallView(tiles: ..., lightingAnimator: lighting)
  ```
  Then capture by launching with that env var set.
