# M9 — Resonant UI (macOS)

Replace the current macOS shell (folder prompt → tile wall + `PlayerChrome` strip) with the full **Resonant** experience as captured in the design hand-off bundle. macOS is the source of truth for the design; iPad and tvOS are downstream variants (M10 / M11).

The product is renamed **Resonant** (codename Reborn Zune). The mark is the "Stack" logo bundled as SVG in `assets/`.

The existing tile wall + Metal lighting pipeline (`TileWallView`, `LightingModifier`, `MusicTileBuilder`, `TileEntryAnimation`, `TileFlipCoordinator`, `LightingShader.metal`, etc.) is **preserved** and used as the full-bleed backdrop of the Now Playing screen only. Every other screen in this milestone is new SwiftUI built against the Resonant design tokens.

The existing core (`Music` / `Album` / `Artist` / `PlaybackEngine` / `NowPlayingCenter` / `FolderLibrarySource` / `LibraryFolderStore`) is preserved unchanged.

Where `Weight` maps to Barlow `200` (`.ultraLight`) and `300` (`.light`).

## 2. App skeleton

`Apps/macOS/ContentView.swift` is rewritten. The new top-level structure:

```swift
ResonantApp(library:, engine:)        // Sources/RebornZuneCore/Views/Resonant/
  ├─ TweaksHost (preserved — debug-only)
  └─ ResonantWindow                   // applies paper background, font defaults
       ├─ MacOSChrome (traffic-light region; not the actual buttons — those
       │  come from the real NSWindow; this is just the empty 36pt top band)
       └─ AppShell
            ├─ PivotNav             (hidden when route == .nowPlaying)
            ├─ ScreenRouter         (route → screen)
            └─ MiniPlayer           (hidden when route == .nowPlaying)
```

State container:

```swift
@MainActor @Observable final class ResonantRouter {
    enum Route: Equatable {
        case home, albums, playlists, artists, search
        case album(Music.Album.ID)
        case playlist(PlaylistID)
        case artist(String /* name */)
        case nowPlaying
    }
    private(set) var route: Route = .home
    private(set) var history: [Route] = []
    func go(_ r: Route)
    func back()                       // pops history; no-op when empty
    var canGoBack: Bool { !history.isEmpty }
    var backLabel: String?            // "Albums", "Today", …
}
```

Routing rules match `app.jsx`:
- `go()` no-ops if the next route equals the current one (no history pollution).
- History cap = 50.
- The active "pivot" is derived from the route: `album → albums`, `artist → artists`, `playlist → playlists`.

## 7. Marquee component

Port `marquee.jsx`: a SwiftUI view that measures its child's intrinsic width vs container, and if overflowing scrolls left in a continuous loop at 60pt/s with 80pt gap between repeats, 1.4s pause at start, hover-to-pause, right-edge fade mask. If not overflowing, render the child once with no animation.

API:
```swift
struct ResonantMarquee<Content: View>: View {
    var speed: CGFloat = 60
    var gap: CGFloat = 80
    var pauseMs: Int = 1400
    @ViewBuilder var content: () -> Content
}
```

Apply to: home panorama titles, artist detail name first+last line, Now Playing track title (none of which currently overflow with sample data — this is a safety net).

`Sources/RebornZuneCore/Views/Resonant/ResonantMarquee.swift`.

## 8. Data binding

The macOS app reads from the existing `LibraryFolderStore` + `FolderLibrarySource` to load the user's music. Mapping to Resonant data:

| Resonant entity | Backed by |
|---|---|
| `Album` | `Music.albumTitle` grouped via `LibraryGrouping` (already exists) |

## 12. Notes for the executor

- **Read the source first.** Every layout decision in §5 is pulled from a specific JSX file. When the spec is ambiguous, re-open that file. The chats also call out a lot of late-stage corrections (panorama peek width, back-arrow optical centering, fade-tile overflow, single-weight phrases) — these are critical, not optional.
- **Single-weight phrases.** Never mid-phrase mix weights (the chat is emphatic about this). Within a single title line use one Barlow weight; the line break and `ink2` color carry the rhythm.
- **Optical centering of the pivot back chevron.** `translateY(+6pt)` exactly. Do not "fix" this — it was the subject of an entire screenshot-validation loop.
- **Cover generator determinism.** Same seed → same variant. Use the same FNV-1a hash as `cover.jsx#_hash` so future cross-platform comparisons match.
- **Now Playing tile wall.** Keep the existing `TileWallView` underneath. Apply the 3 tint overlays as SwiftUI `.overlay()` layers above the tile wall. The 2D grid mosaic shown in the prototype's `now-playing.jsx` is the **layout reference** for what the user already sees from M5 — we are NOT reimplementing the mosaic; we're reusing what's there.
- **Marquee.** SwiftUI doesn't have a built-in marquee. Use a `TimelineView` with a `transformEffect` and a `ResizeObserver`-equivalent (PreferenceKey on the content). Hover-pause via `.onHover` if the device supports it.
- **Fonts.** Bundle Barlow Condensed (200/300/400/500/600), Inter (300/400/500/600), and JetBrains Mono (400/500/600) into the SPM resources. Use `CTFontManagerRegisterFontsForURL` on first use; cache to avoid re-registering.
- **Snapshot regressions.** Once M9 ships, the existing M5 snapshot test (which renders just the tile wall) must still pass — we're not modifying the tile wall code. Verify by re-running the M5 snapshot harness from `_DebugTileWall.swift`.
