`TileWall` view, add the per-tile periodic flip animation and the 14-wave
staggered fade-in entry, fix the warm-delay semantics that drifted from the
UWP source in M4, and introduce a snapshot harness so the evaluator can
headlessly screenshot the actual rendered output for visual verification.

This is the first "you can see it" milestone.

### 2. Periodic tile flip

Per-tile 3D-rotation+opacity flip animation matching `Tile.UpdateThumbnail`
in the UWP original (`Reborn-Zune/Control/Tile.xaml.cs`). The original behavior:

- The tile rotates around the Y axis from 0° to 90° while fading out (200 ms)
- The image source is swapped
- The tile rotates from 270° to 360° while fading back in (~600 ms)
- One tile flips every 5 s, picked randomly from the wall

Implement in `Sources/RebornZuneCore/Views/TileView.swift`:

```swift
public struct TileView: View {
    public let images: [CGImage?]   // current images the tile may cycle through
    public let span: TileSpan
    public let flipPeriod: TimeInterval     // default 5
    public let flipDuration: TimeInterval   // default 1.2
    public let initialDelay: TimeInterval   // default 0 — used by entry waves

    public init(
        images: [CGImage?],
        span: TileSpan,
        flipPeriod: TimeInterval = 5,
        flipDuration: TimeInterval = 1.2,
        initialDelay: TimeInterval = 0
    )

    public var body: some View
}
```

Behavior:
- The view holds an internal `@State var currentImageIndex` and `@State var rotationDegrees`.
- A `Timer.publish` (or `TimelineView` with custom schedule) fires every
  `flipPeriod` seconds (with the per-tile `initialDelay` offset).
- On each fire:
  - Animate `rotationDegrees: 0 → 90` and `opacity: 1 → 0` over `flipDuration / 6` (200 ms when default 1.2 s).
  - Increment `currentImageIndex` (mod images.count).
  - Animate `rotationDegrees: 270 → 360` and `opacity: 0 → 1` over `flipDuration * 5/6` (1.0 s).
- Apply `.rotation3DEffect(.degrees(rotationDegrees), axis: (0, 1, 0))` and `.opacity`.

If `images` has count ≤ 1, no flip occurs (the tile stays static). Tests verify
this behavior.

The `flipPeriod` is the global cadence for the whole wall; the original
chose a single random tile every 5 s. Per-tile staggering by `initialDelay`
prevents synchronized flips. The wall constructor should assign deterministic
or pseudo-random `initialDelay` values spread over `[0, flipPeriod)`.

### 3. Staggered entry waves

Match the UWP's 14-wave entry animation
(`Reborn-Zune/Control/VariableSizedWrapPanel.cs:691–908`) — each wave delays by
80 ms (waves 1–14 → delays 0, 80, 160, ..., 1040 ms), each wave fades in
opacity 0→1 over 450 ms with a scale effect 0.7→1 over 600 ms.

Implement in `Sources/RebornZuneCore/Views/TileEntryAnimation.swift`:

```swift
public struct TileEntryAnimation: Sendable {
    public let waveCount: Int                 // default 14
    public let waveDelayStep: TimeInterval    // default 0.08
    public let opacityDuration: TimeInterval  // default 0.45
    public let scaleDuration: TimeInterval    // default 0.6

    public init(...)

    /// Returns the (delay, opacityDuration, scaleDuration) for the wave at index `waveIndex`.
    /// Index is taken modulo waveCount.
    public func parameters(forWave waveIndex: Int) -> (delay: TimeInterval, opacityDuration: TimeInterval, scaleDuration: TimeInterval)
}
```

The wave assignment to tiles is **deterministic given a seed** (so screenshots
reproduce). Default seed: 0. The assignment is pseudo-random — each tile is
assigned wave `index = SeededRNG(seed).next() % waveCount`.

### 4. Integrated `TileWallView`

The flagship view that brings everything together.

```swift
public struct TileWallView: View {
    public let tiles: [TileWallEntry]            // ordered list of tile entries
    public let unitSize: CGFloat                 // default 70
    public let lightingAnimator: LightingAnimator?  // nil = no lighting
    public let entryAnimation: TileEntryAnimation
    public let entrySeed: UInt64                 // for wave assignment

    public init(
        tiles: [TileWallEntry],
        unitSize: CGFloat = 70,
        lightingAnimator: LightingAnimator? = LightingAnimator(),
        entryAnimation: TileEntryAnimation = TileEntryAnimation(),
        entrySeed: UInt64 = 0
    )

    public var body: some View
}

public struct TileWallEntry: Identifiable, Sendable {
    public let id: UUID
    public let images: [CGImage?]   // images this tile may cycle through
    public let span: TileSpan

    public init(id: UUID = UUID(), images: [CGImage?], span: TileSpan)
}
```

Composition:
- `VariableSpanLayout(unitSize: ...)` arranges the tiles
- Each child is a `TileView` with `images`, `span`, and a deterministic
  `initialDelay = (Double(index % 8) / 8.0) * flipPeriod` (spreads flips across the cycle)
- Each child also gets the entry-wave delay/duration applied via
  `.opacity` + `.scaleEffect` on `onAppear`
- The full `VariableSpanLayout` is wrapped in `.zuneLighting(animator: lightingAnimator)`
  if `lightingAnimator` is non-nil
- The view background is `Color.black` to match the UWP

### 5. Snapshot harness

Headless visual verification needs the app to render a known scene to a PNG
and exit. This avoids TCC permission issues for screen capture and gives
deterministic output.

#### `Sources/RebornZuneCore/Views/SnapshotHarness.swift`

```swift
import SwiftUI

#if DEBUG
public enum SnapshotHarness {
    /// Reads `REBORN_ZUNE_SNAPSHOT_PATH` from the environment.
    /// If set, returns the path; the app should render the configured view
    /// to PNG at that path and exit(0). If unset, returns nil.
    public static var requestedOutputPath: String? {
        ProcessInfo.processInfo.environment["REBORN_ZUNE_SNAPSHOT_PATH"]
    }

    /// Reads `REBORN_ZUNE_SNAPSHOT_TIME` for deterministic animation freezing.
    /// Returns 30.0 if unset. The lighting state is rendered as if `time` seconds
    /// had elapsed since launch.
    public static var requestedSnapshotTime: TimeInterval { ... }

    /// Render the supplied view at the given pixel size to PNG at outputPath
    /// using SwiftUI ImageRenderer. Synchronous. Returns true on success.
    /// Best-effort: ImageRenderer is known not to apply Metal `.colorEffect`
    /// in some configurations; if so, fall back to a screen-capture approach
    /// (out of scope here).
    @MainActor
    public static func render<V: View>(_ view: V, size: CGSize, outputPath: String) -> Bool
}
#endif
```

Behavior of `requestedSnapshotTime`: the value is in seconds since "launch t=0".
The view itself must accept a `frozenTime: TimeInterval?` parameter or use a
`TileWallView` factory that produces a non-animating snapshot.

#### Snapshot-friendly `TileWallView` static rendering

Add to `TileWallView`:

```swift
public extension TileWallView {
    /// Returns a view rendering the tile wall in a frozen state at the
    /// given time. No animations run; the lighting parameters are computed
    /// at `frozenTime` exactly.
    static func staticSnapshot(
        tiles: [TileWallEntry],
        unitSize: CGFloat = 70,
        lightingAnimator: LightingAnimator? = LightingAnimator(),
        frozenTime: TimeInterval,
        panelSize: CGSize
    ) -> some View
}
```

The static snapshot:
- Skips `TimelineView`; computes lighting params once and uses `.colorEffect`
  with constant arguments
- Skips entry waves (tiles fully visible)
- Skips flip animation (each tile shows `images[0]`)
- Renders deterministic output for a given input

### 6. App-side snapshot integration

Modify `Apps/macOS/ContentView.swift`, `Apps/iPadOS/ContentView.swift`,
`Apps/tvOS/ContentView.swift` to handle snapshot mode:

```swift
import SwiftUI
import RebornZuneCore

struct ContentView: View {
    var body: some View {
        #if DEBUG
        if let path = SnapshotHarness.requestedOutputPath {
            SnapshotView(outputPath: path)
        } else {
            DefaultContent()
        }
        #else
        DefaultContent()
        #endif
    }
}

private struct SnapshotView: View {
    let outputPath: String
    var body: some View {
        TileWallView.staticSnapshot(
            tiles: SyntheticTiles.sample(),
            unitSize: 70,
            frozenTime: SnapshotHarness.requestedSnapshotTime,
            panelSize: CGSize(width: 1280, height: 720)
        )
        .frame(width: 1280, height: 720)
        .onAppear {
            DispatchQueue.main.asyncAfter(deadline: .now() + 0.5) {
                _ = SnapshotHarness.render(
                    TileWallView.staticSnapshot(
                        tiles: SyntheticTiles.sample(),
                        unitSize: 70,
                        frozenTime: SnapshotHarness.requestedSnapshotTime,
                        panelSize: CGSize(width: 1280, height: 720)
                    ),
                    size: CGSize(width: 1280, height: 720),
                    outputPath: outputPath
                )
                exit(0)
            }
        }
    }
}

private struct DefaultContent: View {
    var body: some View {
        // M5: show the live tile wall with synthetic tiles for visual demo
        TileWallView(tiles: SyntheticTiles.sample())
    }
}
```

(Use platform-appropriate tweaks where SwiftUI APIs differ.)

## Notes for the executor

- `ImageRenderer` may NOT apply Metal `.colorEffect` shaders depending on the
  SwiftUI version. If snapshot output is missing the lighting wash, document
  this in your report and switch to using `xcrun simctl io <UDID> screenshot`
  for visual verification (the iOS/tvOS sims render Metal correctly). The
  snapshot harness is a convenience; simctl is the source of truth.
- Place a placeholder render call after the actual view is on screen. Use
  `DispatchQueue.main.asyncAfter(deadline: .now() + 0.5)` or a similar
  brief delay so the view tree is fully laid out before rendering.
- `exit(0)` after snapshot is intentional — we don't want the app sticking
  around after the screenshot is captured.
- For tvOS the focus engine doesn't matter for snapshot mode; the snapshot
  view is purely declarative. No focus management needed.
- Sythentic gradient `CGImage`s: use `CGContext.makeImage` with a small
  `CGGradient` drawn into a 256×256 RGBA buffer.
- For the per-tile `initialDelay` distribution, deterministic-by-index is
  fine — `Double(index % 8) / 8.0 * flipPeriod` gives 8 distinct stagger
  buckets evenly spread across the cycle.
